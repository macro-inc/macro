# Native batch queue

`NativeBatch` owns ordered generated operation intents. It does not store or edit
node fields, fabricate references, allocate keys, or schedule editor updates.
`begin` records the expected published version and copies the generated begin
configuration without calling native code. The first `send` folds that begin
into the real batch request. Later sends use only the acknowledged update ID and
mutation epoch, preserving the pending version across public updates in one job.

Enqueuing transfers ownership of the generated intent and its argument arrays;
the internal producer must not subsequently mutate or reuse those arrays. The
queue does not clone opaque values or repeatedly encode every individual write.

The backend supplies the actual session transport, clocks and acknowledgement
consumer. It enqueues constructor/field operations and calls `send(false, leases)`
at semantic barriers and the end of each public update. Microtask or discrete
admission uses `send(true, leases)`. Both requests use owned encoded bytes because
the Bebop writer can be reused by a nested host callback. The scheduler decides
when to call each phase; this class does not combine normalization and admission.

The consumer applies every acknowledged delta and selection sidecar before
surfacing an encoded failure. A typed failure consumes its successful prefix,
partial failing operation and skipped suffix: none is automatically replayed.
The same pending scope remains available for an explicit caught-error retry
until a receipt actually publishes or retires it. A finalization failure may
accompany a real publication: apply that receipt before surfacing the failure,
and never retry admission or claim rollback. Operation failures cannot publish.
An actual no-op retirement returns the previously committed graph version,
including version zero, rather than the burned pending version. Both terminal
receipts block further sends until the backend calls `retire`.
Invalid/missing acknowledgements reject further sends until the backend performs
real native discard and then calls `retire`. Callback reentry must use the static
scoped native transport, never recursively call this session driver.

If applying an already validated terminal receipt throws, the native retirement
is known and cannot be rolled back by discard. The driver requires disposal;
it does not permit another begin, send or retirement reset on that instance.

`retire` is an explicit backend acknowledgement of actual publication, no-op
retirement or successful discard. In particular, a changed=false normalization
reply alone is not permission to drop a pending native scope. Lease release and
version collection remain separate responsibilities of the real backend.

The focused tests exercise the queue and generated byte protocol with literal
receipts. They do not implement a native model and are not initializer, full
plugin, crossing-budget or compact native adapter acceptance. The actual native
compact consumer, creation stages, capture leases and lifecycle wiring are
required before enabling this driver in the production initializer.
