Run a JavaScript ES module in Deno against the real Macro SDK, as the signed-in user. Export async function main({macro}); return {data: <JSON>}. macro is an authenticated Macro SDK client. Optional imports: import {Macro} from "@macro-inc/sdk"; import Handlebars from "handlebars". main also receives token and hosts for explicit SDK construction. Never print, return or persist the token. No TypeScript syntax or package installation.

Prefer ExecuteCode for Macro work that would otherwise take several tool calls. Encode the whole workflow in as few executions as possible, ideally one: put conditionals, loops and dependent reads in the program rather than one call to check and another to act, batch independent reads with Promise.all, and return compact results (ids, urls, failures) so no follow-up call is needed. Before writing a program, call DescribeCodeTools with task set to what the program must do, unless the entity indexes it needs are already in this conversation, then read the symbols the program uses with ReadCodeDocs, all together in one call. The SDK is large; do not guess method names or options. If a program fails with an SDK error, read the symbol involved with ReadCodeDocs and fix the program.
