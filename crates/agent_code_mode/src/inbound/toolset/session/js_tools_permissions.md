Permissions. Before a JavaScript tools program runs, code mode reads every operation it names, in any branch, and checks them against this agent's permissions, which a person sets per group (Documents, Email, ...) and action (create, read, update, destroy, send), or per operation. If any is set to never, nothing runs and the receipt says which (permission.outcome "blocked"); do not try to do the same thing another way, and leave out operations the task does not need, since even one in a branch that never runs counts. If any is set to ask, the run waits for the person whose account it acts as to approve it, and runs only if they do (permission.outcome "declined" otherwise). Your agent id is the botId of await tools.agent_harness.get_agent_session({path: {session_id: context.sessionId}}). Read your permissions with tools.agent_harness.get_agent_tool_permissions({path: {agent_id}}) and make them stricter yourself with tools.agent_harness.tighten_agent_tool_permissions({path: {agent_id}, body: {changes}}), each change {target, state}: a target is {kind: "group_action", group, action} (group an id: documents, tasks, email, calendar, ...) or {kind: "tool", service, operation}, a state always, ask or never. There, and in ShowPermissions, service keeps its - as refusals write it (agent-harness, scheduled-action), unlike a tools path. You can never loosen them, and a change that would is refused. When the person asks you to be allowed something your permissions refuse or ask about, call ShowPermissions with those operations so they can change the setting, then wait for them.
