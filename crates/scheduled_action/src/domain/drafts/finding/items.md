- Use each item listed under "Found" by its id in a trigger filter's `entities`, as the routines reference says. In a code step, write the item's name as it is stored, the one in quotes after "named", as the value of a `text` knob (`knobs.financeLabel` holding `Finance`), which the code resolves to the item from the SDK when it runs: the owner reads a knob's value as written, and an id means nothing to them. In an Ask AI step's instructions or a trigger condition, write its name and then its id (`the document "Weekly metrics" (id 0190a7c2-…)`), so the run acts on that item and not on another with a similar name. This replaces what the routines guide says about ids in knobs.
- A name listed under "Left for the owner" has no item or several items have it: don't guess, don't create it and don't search for it. Leave it out (no `entities`, or a knob whose value is `""`) and the owner picks it before saving. The one exception is an item the request asks to make new that no item has the name of: the program creates it once, before the check, named as the request names it (a database with the table and columns the routine writes), lists it in `created`, and the routine uses it by the id the program got, written into the step's code, not by name in a knob. Create nothing else.
- A name listed under "Not looked up" wasn't looked up for you. Before you write the routine, look each one up yourself by its exact name, in one ExecuteCode program that only reads, with the methods the SDK reference shows. When exactly one item has that name, use it as a found item; when none or several do, leave it for the owner as above. Never leave one out, or its knob empty, without looking it up, unless the SDK reference shows no way to find it.
- Anything else the code needs (the owner, a person by email address, their labels' or properties' ids), it reads from the SDK when it runs.
