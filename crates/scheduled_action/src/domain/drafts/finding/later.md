A routine that does something once, later, for each item a run finds or an event brings (a reminder the day before each task is due, a follow-up two days after a channel is created) schedules that work from a code step, one sub-routine per item: `await macro.routines.create({name, trigger, steps}, { key })`. Give it a `{type: 'once', at}` trigger, never a `cron` one, and a `key` naming the item, so a later run updates that sub-routine instead of adding another. The code works `at` out from the item and `run.at` as a time on the owner's clock in `run.timezone` (9am the day before is 9am there, not in UTC), and skips an item whose time has passed: a past `at` runs as soon as it is saved. The sub-routine's steps do the later work and follow the rules for steps here: to tell the owner, it ends with its own Ask AI step, whose instructions name the item by id. So the scheduling is never this routine's Ask AI step's to do. Work that repeats until something happens (a check every morning until a thread is answered, a weekly check on each new task while it is open) is not a sub-routine, even when an event brings the item: it is a routine on that schedule looking for what is still open. A routine has at most 50 sub-routines that haven't finished, and a create past that is refused: a `once` one finishes when it has run, a `cron` one, even switched off, only when deleted. Only the routine's runs create sub-routines, never your program, and the check doesn't see them: check only the routine you hand back. The step's `sentence` says what it schedules and when.
