A routine the catalog lacks, for a stream they act on every week: `{ kind: 'routine', routine, created, reason, surfaces, keepProbability, card }`, where `routine` is written exactly as `macro.routines.check` takes it, following the routines guide below. Build it on what reaches Macro: {start}. Make what the work needs, where the user would look for it: a task for each step they must take, {crm}and one task or document for what many messages add up to or for a log they keep, never a task for each of those messages. Either way the routine does the reading: what it writes holds the facts the user needs, taken from the mail (who, what, amounts, hours, dates, and each next step they agreed to as a task of its own), never a task that only points at a message or pastes it in. Code can't pull those out of a message, so a routine that needs them ends with an Ask AI step that reads the mail and writes them. It is checked as saving checks it; fix what the answer reports and suggest it again. Never one that sends, forwards, deletes, shares or pays anything, and never one that acts as the user. It is saved switched off; the user reviews it first. It also shows in the user's Suggestions feed: `card` is `{ title, importance, categories }`, a title of a few words saying what it does for the user, an importance from 0 to 100 (how much they would regret missing it this week), and any of the categories `important`, `revisit`, `save_money`, `make_money` that fit. A catalog routine takes no `card`.
