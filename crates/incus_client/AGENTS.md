# incus_client

## What it is

Rust client for the Incus REST API, for the Macro computers fleet adapter
that creates, powers, and inspects box VMs on Incus hosts.

## How it works

`spec/rest-api.yaml` (upstream Swagger 2, pinned to nixpkgs `incus-lts`) is
converted to OpenAPI 3, trimmed and reshaped by `spec/patch.py` into
`spec/openapi.json`, and generated by progenitor into `src/generated.rs`.
`InstanceInfo` retains device overrides so fleet reconciliation can check root
and state volume limits against recorded sales.
`IncusClient` wraps the generated client with mTLS, error-envelope mapping,
and operation waiting.

## Start here

- `src/client.rs`: every method the fleet adapter calls, including non-interactive root `exec` with checked exit status, custom block volumes for computer data disks (create, attach, delete), `rebuild` from a new image, and `run_operation`.
- `src/error.rs`: `IncusError`; `NotFound` is how callers detect drift.
- `spec/patch.py`: the endpoint allowlist and the reshaping progenitor needs.

## Names

- Pass validated `InstanceName`, `ImageAlias`, `ProfileName`, `StoragePoolName`, and `StorageVolumeName` through the hand-written API. Computer instance names use `mc-<simple UUID>`.
- Keep inventory instance names as untrusted strings: listings include unrelated instances that the fleet must ignore by ownership metadata.
- Validate string deserialization through `TryFrom<String>` while retaining transparent serialization.

## Scope

- Owns: the Incus wire API, TLS pinning, operation waiting.
- Not here: fleet policy (naming, profiles, retries, drift handling), which
  belongs to the fleet adapter.

## Recipes

- Add an endpoint: add it to `KEPT_OPERATIONS` in `spec/patch.py` →
  `nix develop --command crates/incus_client/regen.sh` from the repo root → a
  method in `src/client.rs`.
- Bump Incus: set `INCUS_VERSION` in `regen.sh` to
  `nix eval --raw --inputs-from . nixpkgs#incus-lts.version`, then
  `nix develop --command crates/incus_client/regen.sh --fetch` from the repo root.
  The dev shell pins swagger2openapi 7.0.8 and the repository Rust toolchain.

## Checks

- `cargo test -p incus_client`
- After `regen.sh`: `cargo clippy -p incus_client` and commit `spec/` and
  `src/generated.rs` together.

## Gotchas

- Never edit `src/generated.rs` or `spec/openapi.json` by hand; change
  `spec/patch.py` for spec changes or `regen.sh` for generator formatting.
- Keep `spec/rest-api.yaml` verbatim from the pinned upstream release; its
  contact has a path-scoped exception in `tooling/pii/exceptions`.
- Emit generated docs as line comments in `regen.sh`; indented multiline block
  comments turn prose into Rust doctests.
- Incus's `?recursion=1` variants are separate path strings upstream; the patch
  folds them into the plain path with a required `recursion` parameter, so
  generated list methods return full objects and always get `1`.
- Errors are declared as `4XX`/`5XX` ranges, not `default`: progenitor treats
  `default` as a second success type and panics.
- The server certificate is pinned by exact bytes; hostname and expiry are not
  checked (Incus certificates are self-signed and the host may be reached
  through a tunnel).
- `delete` and `instance` return `IncusError::NotFound` for a missing
  instance; the caller decides whether that is success. Incus refuses to delete
  a running instance; stop it first.
- Require explicit `IncusEndpoint::timeouts` (request, connect, operation wait
  seconds/count and state-change seconds); no transport defaults. `run_operation`
  gives up with `OperationTimedOut` at the configured limit; the operation
  keeps running on the host.
- `remove_config_key` is a GET plus an ETag-guarded PUT (PATCH cannot remove a
  key); a concurrent edit fails with a 412 `Rejected`.
- No trace headers are sent; Incus does not read them. Methods open
  `incus.*` spans instead.
- Progenitor takes one success type per operation; `SUCCESS_STATUS` in
  `spec/patch.py` picks it where Incus documents both a sync and an async
  success (volume create is sync, rebuild is async).
- Deleting an instance leaves attached custom volumes; `delete_volume` them
  after the instance.
