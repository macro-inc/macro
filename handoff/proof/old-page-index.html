Starting a routine from a webhook

Recorded on commit 919f20d064bf39432a2bdc19f95e71412b168e02 (PR head)

The real web app and services, built from that commit, on a local Macro stack, driven by a browser script as a synthetic account. The first routine is given its trigger in the editor's Add trigger menu; deliveries come from curl. Every secret is blurred on screen and written as mrw_<secret> below; the API key is written as <api key>.

What happened

  • 202A JSON POST to the URL started one run, which shows the body as sent under Webhook body.
  • 404The bearer form with no Authorization header was refused.
  • 404A made-up secret was refused, with the same answer.
  • 404After New URL, the old URL was refused at once.
  • 202The new URL started a second run.
  • 202A routine whose code step reads trigger.item.webhook.json ran on a POST; the step's output shows "build": 5107 and "failed": 7 from the posted body.
  • 403With the owner's own API key, reading, making and deleting the URL were all refused: "only the routine's owner can manage its webhook, from their own account".
  • 202The code routine's URL still worked after those refusals.

Reopening the panel after closing it shows only when the URL was made; the secret is gone from the page.

Recording

The whole browser session, start to finish (about four minutes, mostly waiting on runs). Terminal deliveries happen between the panel closing and the Runs tab opening.

In the editor

The code step

The second routine has one code step and only the webhook event trigger, made through the API; its URL was made through the owner route.

export async function main({ trigger }: StepContext) {
  if (trigger.kind !== 'event') return null;
  const sent = trigger.item.webhook?.json;
  if (typeof sent?.build !== 'number') return null;
  return { build: sent.build, status: sent.status, failed: sent.tests?.failed ?? null };
}

Notes

  • The first routine's runs end in "failed" only because this stack starts without AI computers (--no-computers); the start, the trigger and the body are what this proof covers. The code routine needs no AI and succeeds.
  • With the stack's AI computers on, the stack points the public gateway at an in-network host, so a URL made locally names a host a terminal cannot reach. This recording ran without computers so the URLs use the stack's public proxy. Dev and production are unaffected.
  • The API key was made for the same account that owns the routines, so the 403s are the API-token refusal, not an ownership check.
