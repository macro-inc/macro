# xtask_test_targets

## What it is

`cargo x test-targets`: the CI guard (`check` job of the cloud storage code
check) that keeps the workspace from building test binaries that run no test of
their own, and from marking a target `test = false` while it still holds tests.

## Start here

- `src/main.rs`: the three rules, the module-tree walk and test detection.

## Checks

- `cargo test -p xtask_test_targets`
- `cargo x test-targets`

## Gotchas

- Detection is static: a module reached only through a macro (`cfg_if!`), or a
  test generated by a proc macro other than a `*test` attribute or `proptest!`,
  is invisible. Teach `tokens_hold_test` the new form rather than adding
  exceptions.
- `[[test]]` targets with `test = false` are exempt: `service_binary_builds`
  holds a test on purpose so `build-service-bins` can build the real binaries.
