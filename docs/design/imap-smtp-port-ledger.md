# IMAP and SMTP port coverage

This inventory follows the engine, account, network and worker rows in the EmailEngine v2.89.0 port plan. The upstream revision is `48f2fd0744ea0e35e7d39359aa3c547f90eca37a`. Its IMAP dependency is imapflow 2.12.1 and its SMTP dependency is nodemailer 10.6.0. Macro uses async-imap for IMAP and a Rust submission transport. The provider speaks a private HTTP API to the existing email service. [Architecture](../architecture/imap-engine.md) · [Protocol lab](../../docker/imap-lab/README.md)

Paths below are relative to [the engine's Rust source](../../crates/imap_engine/src/) unless they start with a workspace directory. Test names identify runnable checks. A listed implementation without an interoperability test is a narrower claim than observed vendor behavior.

The protocol lab checks real TLS, login, isolated inboxes, flags, moves and SMTP delivery. The public Rust journey passed connection, import, byte-exact attachment download, cross-owner refusal, settings CAS, filing and captured SMTP delivery through the email service. Chromium passed the desktop and mobile journeys. Each signed in with its verified address, opened the imported conversation, delivered a reply to an independent Mailpit receiver, saved folder preferences and reopened them. Local Tempo recorded 17 spans for each enrollment. The browser’s connect action led to the public email HTTP request and the private IMAP service’s verification and connection spans. The local fixtures cannot certify external Gmail, Exchange, iCloud or Yahoo server behavior. Inspect each test's result when recording release evidence; a registered test or generated schema alone cannot verify a running mailbox.

Additional release measurements include a repeated SELECT refusal against a real server, a reset during an interrupted import, live Gmail label behavior, and stale observers during failover. A local debug build scanned 100,000 messages on a real CONDSTORE server in 7.655 seconds, with a highest modification sequence of 101, 25.48 MB of headers, and a peak RSS of 78,992 KiB. The remote corpus contained 80.78 MB. A sentinel confirmed bodies stayed remote until a separate, explicit fetch. The local protocol run passed all 66 engine cases, including Dovecot, Stalwart, an injected lost final SMTP acknowledgment, Gmail label organization, connection reuse and host circuit recovery. The SMTP receiver's saved representation may add Bcc from its envelope; a wire-level check uses the Dovecot submission relay to distinguish transmitted headers from receiver enrichment. QRESYNC, IMAP OAuth and remote editable drafts are explicit exclusions of the original release scope.

| Behavior | Implementation and evidence |
| --- | --- |
| Per-account connections | The scheduler and `actor.rs` fence the primary with a renewable account lease; a command lease and one optional watcher cover concurrent work. The two-replica tests exercise takeover. |
| Main folder | The default primary is Inbox. With X-GM-EXT-1 and a listed All Mail folder, the primary waits there instead; hiding All Mail restores ordinary folder sync. Local Dovecot exercises the ordinary Inbox case. |
| Sync state machine | `protocol.rs::snapshot` selects a full or CONDSTORE pass and reconciles UID membership against `service/sync.rs`. `service/test.rs` covers reset, move and ambiguous identity. `service/test/sync_cost.rs` and the 10,000-message PostgreSQL repeat-sync case prove unchanged walks do not save or notify, while physical baselines still persist without a callback. |
| Index | `outbound/postgres/storage.rs` keys message, location, folder, change and draft entries by link. The large-mailbox test preserves unrelated entries during point updates and pages the first 501 membership rows. |
| Events | Folder changes enter durable per-folder journals. `outbound/notifications.rs` wakes the email importer and its existing projection pipeline. |
| IDLE | `domain/adaptive_idle.rs` and `actor.rs` choose bounded restart intervals and persist host observations. Each primary or optional watcher opens a new selected socket per IDLE interval and closes it after DONE; a server without IDLE is polled every 30 seconds. |
| Other folders | Each catalog refresh processes included physical folders and retains excluded folders without retrieving their content. STATUS-only skipping and the timing of intermediate scans depend on the negotiated server capabilities. |
| Burst handling | A watcher uses a bounded debounce and a link-local wakeup; the account owner serializes refreshes. Test a wire burst and count provider scans to establish the work bound. |
| Reconnect | Classified network errors feed cancellable jittered retries. Credential replacement advances sync/grant generations and the settings revision. |
| Login failure | Definite login refusals trigger health handling. UNAVAILABLE, SERVERBUG, INUSE, LIMIT and authenticated-but-disconnected replies leave the credentials usable for retry. |
| UIDVALIDITY change | The cursor contains the folder epoch; stale cursors are rejected and the folder is rebuilt. The move/reset test checks message identity across the transition. |
| Gmail extensions | `protocol/identity.rs` parses native message and thread identities. The Gmail transport plan selects All Mail, Spam and Trash. Organization tests exercise archive, filing, and preservation of system labels during custom label edits. External Gmail behavior still needs the provider-account matrix. |
| Special-use detection | `protocol/folder_roles.rs` elects one destination per role using extension flags, exact localized names, then decorated names. Owner overrides take precedence; a deleted custom destination restores the automatic role. |
| Phantom folders | `domain/folder_health.rs::PhantomFolder` records three SELECT refusals and reprobes when STATUS changes or six hours elapse. The transport persists the skip state and preserves the index on a refused SELECT. |
| Replication lag | Existing mailbox stream import retries recently announced UIDs that cannot yet be read. A genuine absence after retry becomes a removal through the ordinary projection path. |
| Stale folder UID guard | Fetch and mutations select the wire path and verify its UIDVALIDITY before touching a UID. Independent-account and reset tests exercise the identity boundary. |
| Deletes | The organization adapter handles filing, trash and expunge using the resolved role. Permanent expunge requires selective UID handling so another client's pending deletion is preserved. |
| Submit retries | Macro's durable draft worker retries known pre-acceptance failure. `service/send.rs` records an absolute six-minute deadline and a ten-minute penalty. An ambiguous outcome remains terminal for automatic resend. |
| Exactly-once guard | Persisting Unknown before SMTP bounds automatic submission to one attempt across a crash. A crash before the first wire write can therefore leave a conservative unknown outcome. |
| Sent copy | `service/send.rs` persists a Sent-copy attempt before APPEND. After an ambiguous APPEND, restart searches for its Message-ID and cannot append a second copy. An account without a usable Sent destination can still expose a local sent record. |
| Bounces and complaints | The lazy read exposes structured DSN recipients, ARF feedback, original message identity and auto-reply state. Authored fixtures include WorkMail, Zoho and Hotmail dialects. |
| Autodetect | Catalog and guarded anonymous DNS/HTTP resolvers offer endpoints. The account owner confirms the displayed hosts before sending either protocol's password. |
| QRESYNC | The planned incremental path is CONDSTORE CHANGEDSINCE plus membership reconciliation. QRESYNC was deferred in the original plan. |
