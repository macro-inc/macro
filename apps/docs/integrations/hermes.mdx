You can run [Hermes Agent](https://hermes-agent.nousresearch.com/) on your own machine and connect it to a custom Macro agent. `macrod` receives Macro @mentions, starts Hermes over the Agent Client Protocol (ACP), and sends its work back to the channel.

<Warning>
  Hermes runs commands in the repository you configure. Use a dedicated workspace, review its permissions, and keep your Macro agent token private.
</Warning>

## Before you start

You need:

- A machine that can keep Hermes and `macrod` running
- A local copy of the repository Hermes should work in
- A public HTTPS endpoint that forwards webhooks to port `8790`

<Steps>
  <Step title="Create a Macro agent">
    Open **Settings → Bots → Create bot**. Enable **Make this bot a coding agent**, choose the channels it can join, and create it.

    Copy the agent token when it appears. Macro shows it only once. If you lose it, create a new token from the agent's settings page.
  </Step>

  <Step title="Install Hermes">
    Install Hermes with its official installer, complete setup, and verify its ACP adapter:

    ```bash
    curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
    hermes setup
    hermes-acp --check
    ```
  </Step>

  <Step title="Download macrod">
    Open the [latest Macro release](https://github.com/macro-inc/macro/releases/latest) and download the `macrod` archive for your operating system and architecture.

    Extract the archive and make the binary executable:

    ```bash
    tar -xzf macrod-*.tar.gz
    chmod +x macrod
    ```
  </Step>

  <Step title="Expose the webhook port">
    `macrod` listens on port `8790` and receives requests at `POST /macro-events`. Macro must be able to reach that endpoint over public HTTPS.

    The quickest option is a [Cloudflare quick tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/). After you [install `cloudflared`](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/), run:

    ```bash
    cloudflared tunnel --url http://localhost:8790
    ```

    Cloudflare prints a temporary URL such as `https://example.trycloudflare.com`. Append `/macro-events` when you configure `public_url`.

    <Note>
      A quick-tunnel URL changes whenever `cloudflared` restarts. Create a [named Cloudflare tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-local-tunnel/) when you need a stable agent.
    </Note>
  </Step>

  <Step title="Configure macrod">
    Create `macro.toml` beside the `macrod` binary:

    ```toml
    [macro]
    api_url = "https://agent-harness.macro.com"
    storage_url = "https://cloud-storage.macro.com"
    owner_user_id = "macro|you@example.com"
    bot_token = "mbot_..."
    bot_scope = "user"

    [server]
    port = 8790
    public_url = "https://example.trycloudflare.com/macro-events"

    [harness]
    command = "hermes-acp"
    args = []

    [workspace]
    path = "/absolute/path/to/your/repository"
    repo_url = "https://github.com/you/your-repository"
    ```

    Change `you@example.com` in `owner_user_id` to the email address you use to sign in to Macro. Replace `mbot_...` with the token from the first step. For a team-owned agent, use `bot_scope = "team"`.
  </Step>

  <Step title="Start the agent">
    Keep the Cloudflare tunnel running, then start `macrod` from a shell where `hermes-acp` is available:

    ```bash
    ./macrod --config ./macro.toml
    ```

    When `macrod` reports that it is listening for agent triggers, @mention the agent in one of its Macro channels.
  </Step>
</Steps>

## Keep it connected

Both `macrod` and your HTTPS tunnel must stay running. If a quick-tunnel URL changes, update `public_url` in `macro.toml` and restart `macrod`. It will register the new endpoint automatically.
