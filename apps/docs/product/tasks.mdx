Macro Tasks start lightweight enough for a single user but scale easily onto a team, where tasks you create are auto-shared with members. They're @mentionable anywhere in Macro as live, up-to-date pills, sync bidirectionally with GitHub PRs to move status automatically, and are fully accessible to AI clients via Macro's MCP server.

You can reference a task in your channels, in your documents, or with an agent by @mentioning it. Quickly create a task directly from a channel or an email by hovering and selecting the task button.

You can manually review all of your team's tasks in the task view or ask your agent to give you updates on them.

### Assigning agents

Each [agent](/product/agents) you assign to a task starts a session. The task's discussion gets a message that links to it, and the work stays in that session. People and agents can be assigned to the same task. Remove an agent and assign it again to start a new session.

Assign an agent to a project and it starts a session for each task added to that project afterward. Tasks already in the project are not started. Removing the agent stops that for tasks added later. Sessions already running keep going.

### Team level sharing

When you're on a team, a new task is shared with its members unless you turn that off. The switch is labeled **Share with** and your team name, and it starts on. Turn it off and only you and the people you share it with can see the task. Teammates who can see it can view and comment, while you (and the assignee) keep full control over its status and properties. Assigning a task to someone sends them an inbox notification, as does @mentioning a teammate in the task's comments.

**Sharing follows team membership**

- Join a team and you'll see the tasks shared with it, those assigned to you and to others.
- If you're removed from the team, you lose access to them.
- If you're not on a team, your tasks stay private to you.

### GitHub integration

Macro tasks integrate with GitHub: as you create, review, and merge branches, the task automatically moves to "In Progress," "In Review," or "Completed," and the task records which pull request is associated with it. See [GitHub integration](/integrations/github) for setup and details.

### MCP setup

Macro's MCP server lets AI clients like Claude Code, Codex, and Cursor work with your tasks directly. Connect once by going to **Settings → MCP server** (authorize with your Macro account — MCP access is included on every plan, Free included). You can use the MCP server to spin up a task, triage your list, or move something to "In Review" without leaving your editor. Any changes made will show up live in Macro.

**MCP for tasks uses**

- **Create a task**
- **Find your tasks**
- **Read a task**
- **Update a task**

### @mentioning

Tasks are markdown entities, so you can @mention one anywhere else in Macro — in a doc, an email, a chat, a channel, or another task. The mention renders as a live pill that stays in sync with the task's status and title, so wherever you reference it, you're always looking at the current state. Click it to jump straight to the task.

## Projects

A project groups [tasks](/product/tasks). Each project has a status, priority, assignees, due date, a collaborative description, and a discussion thread.

## Creating a project

Choose **Project** from the **Create** menu, or click **New project** in the **Projects** tab in Tasks. Enter a name and optional description, and set **Status**, **Priority**, **Assignees**, and **Due date**.

Projects are shared with your team by default. You can still keep one private: open **Share** and set **Team access** to **No team access**.

## Projects tab

Open **Tasks** and select **Projects**. Press <kbd>cmd</kbd>\+<kbd>f</kbd> to search. Group by status, priority, or assignee. Sort by updated or created date. Filter by status, priority, due date, or **Assigned to me**.

Right-click a project to rename, set status or priority, share, or delete it.

## Project tabs

- **Overview**: properties, description, and discussion. The description supports `/` commands and @mentions, and multiple people can edit it at once.
- **Tasks**: the project's tasks as a list or board. **New task** creates a task in the project. **Add existing tasks** moves tasks into the project.

The side panel shows all project properties. See [Properties](/concepts/properties) for field types and custom fields.

## Adding tasks

Set a task's **Project** property from the pill under the task title, the **Project** column in the task list, or **Add to project…** in the right-click menu. Select multiple tasks to move them together.

A task belongs to one project. Adding it to another project moves it.

Deleting a project does not delete its tasks.

## Agents

Assign an [agent](/product/agents) to a project and it starts a session for each task added to that project afterward. Tasks already in the project are not started. A coding agent can open a pull request from that session, and the task links to it.

## Sharing

Project assignees get edit access. **Share** invites people, sets team access, and copies a link. Sharing a project to a channel posts a card that opens it.
