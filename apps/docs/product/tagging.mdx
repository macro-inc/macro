Use an agent routine to tag incoming emails by customer, project, or topic. The same tags work across emails, docs, and tasks, so you can find the related work together.

Create a [routine](/product/routines#creating-a-routine) with the **New email received** trigger and tell the agent which tags to apply. You can also ask an agent to tag existing work.

## One set of tags

A tag is a [property](/concepts/properties), and because properties are shared across your whole workspace, a single tag namespace spans every block type. Tag an email `marketing` and a task `marketing` and it's the same `marketing`: one color, one filter, one click to see everything carrying it.

Tags are for organizing your work by project, team, or area, like `marketing`, `hiring`, or `q3-launch`. They aren't for tracking status. Status, priority, and assignees are [properties](/concepts/properties) that describe a single item, while a tag is a property that ties related items together across the whole workspace.

## What you can tag

The same tags apply across:

- **Documents** — tag PDFs, other files, and [snippets](/product/snippets)
- **Tasks** — tag a task to group it with related work
- **Emails** — tag a whole thread
- **AI chats** — tag a conversation with an agent
- **Calls** — tag a recording or transcript

## Creating and applying tags

Type `#` in a document to open the tag menu, then pick an existing tag or create a new one. Tags render inline as colored pills, and clicking a pill shows everything else carrying it.

Everywhere else, use the tag panel in the properties window. Select one of your existing tags or start typing to create a new one.

An item can carry as many tags as you like, so the same email or task can sit under `marketing` and `q3-launch` at once.

> If you would like to select or unselect multiple tags, hold <kbd>Shift</kbd> while clicking them.

## Personal and team tags

When you create a tag you choose its scope:

- **Personal** — only you see it. Anyone can create personal tags.
- **Team** — shared with everyone on your team. Creating a team tag requires being on a [team](/account/teams).

Renaming or recoloring a tag keeps its identity, so the change flows to every item already carrying it. Deleting a tag is destructive and it will be removed from everything at once and can't be undone.

## Filtering and search

In any Block, go to **Filter → Tags** to show only the items carrying a tag. To filter across your entire workspace at once, use the same **Tags** chip in the filter menu of [search](/product/search#filtering-by-tags). Select two or more tags and a match-mode toggle appears:

- **Any** — items that have any of the selected tags (the default)
- **All** — items that have every selected tag, for example everything tagged both `marketing` and `q3-launch`

Clicking a tag pill anywhere jumps straight to everything else carrying it.

## Managing your tags

Curate the full set from **Settings → Tags**, which lists your **Personal** and **Team** tags with edit and delete actions and a **New tag** button. It's the place to rename, recolor, or clean up tags without hunting for an item that uses them.

<Note>
  **Tags are not email labels.** Gmail labels, and the folders on an Outlook mailbox, still belong to that account and still drive inbox actions like archive and star. Macro tags are a separate, cross-workspace layer that sits on top — an email thread can carry both.
</Note>

## Tagging with agents

Tell your AI client (Claude Code, Cursor) connected to the [MCP server](/AI/mcp/overview) "tag this thread `marketing`" or "make a `q3-launch` tag and add it to these tasks," and it handles the rest without you leaving your editor.
