# Geofence plugin

## What it is

The native half of location-triggered routines (`trigger.type = "location"`).
It monitors the places routines name with OS geofencing and, on a crossing,
posts `{ fence, on }` to the scheduled-action service's
`/scheduled-actions/location/reports` with the device token, from native code,
so reports arrive while the app is closed. The server never sees a location.

## Start here

- `src/lib.rs`: no Rust commands; `plugin:geofence|<command>` reaches the Swift
  or Kotlin method of the same name in lower camel case.
- `ios/Sources/GeofenceMonitor.swift`: `CLLocationManager`, permission steps,
  nearest-20 region selection, crossing reports and 401/404 handling.
- `android/src/main/java/com/macro/geofence/GeofenceRegistrar.kt`: Play services
  registration; `GeofenceReceiver.kt` reports crossings and restores fences
  after reboot or app update.
- `../../src/lib/core/mobile/native-geofence.ts`: the web binding.

## Boundaries

- Commands: `status`, `request_permission`, `set_device`, `device_id`, `sync`,
  `clear`. Adding one updates `build.rs`, both capability files in
  `../src-tauri/capabilities/`, and `apps/web/native-commands.json`.
- Older native binaries run new web bundles: the binding gates every call on
  `window.__MACRO_GEOFENCE__`, which `src/init.js` defines.
- Report only the transition a fence declares. A 401 forgets the device and
  every fence; a 404 drops that fence. Ignore an answer whose device was
  replaced while the request was in flight.
- Never log tokens, coordinates or place names; fence ids are opaque.
- iOS: create the `CLLocationManager` in `load(webview:)`, not in `init` (see
  `.agents/rules/native/ios-plugins.md`); a background relaunch delivers queued
  crossings once the delegate is set. Monitors only with Always, at most 20
  regions; significant-change monitoring re-picks the nearest when there are
  more. Region monitoring needs no `location` background mode; do not add it.
- iOS shows the Always upgrade prompt once and sends no callback when the user
  keeps When In Use, so `requestPermission` also ends when the app becomes
  active again, or after one second if no prompt covered the app.
- Android: `setInitialTrigger(0)`, so re-registering inside a fence is not an
  arrival. Background location must be requested separately after foreground
  location (Android 11+ ignores it otherwise). At most 100 geofences.
- The token lives in the iOS Keychain (after first unlock, this device only)
  and in private Android preferences (backup is disabled app-wide).

## Checks

- `nix develop .#tauri-linux --command cargo check --manifest-path apps/web/tauri/Cargo.toml -p tauri-plugin-geofence`
  validates the Rust crate and regenerates `permissions/autogenerated`.
- `bun run test src/lib/core/mobile/native-geofence.test.ts src/lib/tauri/native-commands.test.ts` from `apps/web`.
- Swift compiles only in an iOS build; Kotlin in an Android build (`just android-build --debug --apk true --aab false`).
  Exercise arrive and leave with the app terminated on a device or simulator
  (Simulator: Features → Location → custom location / freeway drive).
