# Webhook crate

This crate currently contains the core application-layer webhook pieces for the first iteration.

## Current scope

- Database tables are present for event ingestion, webhooks, deliveries, and delivery attempts.
- The Postgres repository supports creating, loading, patching, and updating webhook validity through the `is_valid` field. It also lists active webhooks whose typed `filters` match an event.
- The inbound Axum API supports:
  - `POST /webhooks`
  - `PATCH /webhooks/{webhook_id}`
  - `POST /webhooks/{webhook_id}/validate`
- Validation sends a signed `webhook.validation.test` event to the webhook endpoint and persists the result by updating `is_valid`.
- Validation attempts are rate limited with the existing `rate_limit` crate. The validation key is `per-user-validate-webhook:{macro_user_id}:{webhook_id}` and the current limit is 10 attempts per 3600-second window.

## Typed filters

Webhooks use a typed `filters` array to decide which events are eligible for delivery. Each filter contains event names and may also restrict delivery to specific entity ids:

```json
[
  {
    "events": ["document.created"],
    "ids": ["doc_123"]
  }
]
```

`events` is required on every filter. `ids` is optional; when it is absent, that filter matches all entity ids for its events.

## Database storage and matching

Filters are stored in the `webhook.filters` `JSONB NOT NULL` column. The column has the `webhook_filters_is_array` check constraint so stored filter data is always an array:

```sql
CHECK (jsonb_typeof(filters) = 'array')
```

The `webhook_filters_gin_idx` index is a GIN index using `jsonb_path_ops` on `filters`. It supports containment probes on keys inside filter elements, including `events` and `ids`. The canonical matching query used by `WebhookRepo::list_active_webhooks_matching_event` combines an index-backed containment predicate for the event with an exact JSONPath recheck for the same filter element's event and entity-id semantics:

```sql
WHERE w.filters @> jsonb_build_array(jsonb_build_object('events', jsonb_build_array($2::text)))
  AND jsonb_path_exists(
      w.filters,
      '$[*] ? (@.events[*] == $event && (!exists (@.ids) || @.ids == null || @.ids[*] == $id))',
      jsonb_build_object('event', $2::text, 'id', $3::text)
  )
```

## Temporary limitations

- Webhook IDs currently use prefixed UUIDv7 strings (`wh_<uuid_v7>`). They can be swapped for true ULIDs later.
- Webhook signing secrets are generated by the service and stored in plaintext in `signing_secret`, matching the existing bot secret storage approach.
- Custom headers are stored as JSON in the `headers` column.

## Intentionally out of scope

Delivery workers, SQS/SNS infrastructure, event ingestion, redelivery, and auto-pause behavior are intentionally out of scope for this crate iteration.
