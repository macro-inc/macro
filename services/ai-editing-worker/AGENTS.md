# ai-editing-worker

## What it is

Part of Documents' AI editing feature — a Cloudflare Worker that joins a
document as a real Loro collaboration peer and streams AI-driven edits
through it. `AI_EDITING.md` has the full flow (interpreter/supervisor/writer
agents, the QuickJS sandbox → `DocumentOp[]` → animation pipeline). Read it
before touching the edit flow.

## Start here

- `src/index.ts` / `src/endpoints/index.ts`: the hono app and route table
  (`POST /edit` and friends).
- `src/run-edit.ts`: `runEditSession` — joins the sync-service WebSocket,
  drives the agents, flushes commits back.
- `src/ai-editing/`: the agent loop, prompts, tools, and op queue.
- `src/endpoints/`: one file per surface — `edit.ts`, `docx.ts`, `forms.ts`,
  `spreadsheet.ts`, `comment-mark.ts`.
- `src/sandbox.ts` / `scripts/generate-sandbox.ts`: the QuickJS sandbox the
  model's generated code runs in (regenerated by `prebuild`, not hand-edited).

## Scope

- Owns: the AI document-editing session (joining the doc, agent orchestration,
  applying edits), DOCX/forms/spreadsheet AI endpoints, and comment-mark anchoring.
- Not here: the Loro/sync-service wire protocol itself, shared with the web
  app via `@macro-inc/collaboration`; browser auth and sync HTTP policy stay
  in `apps/web`.

## Recipes

- Add or change a prompt section: `src/ai-editing/prompts/index.ts` composes
  `GROUND_RULES`, `TEAM`, `EDITING_RULES`, `API_COMPLETE`, plus one role file
  per agent — put a rule in the one shared section both roles need, not in
  both role files.
- Add a new AI editing endpoint: `src/endpoints/<name>.ts` → register in
  `src/endpoints/index.ts`.
- Change the sandboxed edit API: `src/ai-editing/doc/` or `src/ai-editing/editor/`
  → `scripts/generate-sandbox.ts` (regenerates `src/editor-sandbox-code.ts`).

## Checks

- `bun run type-check` (`tsc --noEmit`).
- `bunx vitest run` for most unit tests (co-located `*.test.ts`); spreadsheet
  has its own configs: `bun run test:spreadsheet` and
  `bun run test:spreadsheet:integration`.
- `just dev` for `wrangler dev --env local`. (`just dev-local` points at a
  `src/server.ts` that no longer exists.)

## Gotchas

- This worker never deploys without explicit approval — `just deploy-dev` /
  `deploy-prod` run `generate-sandbox` first; don't run them unprompted.
