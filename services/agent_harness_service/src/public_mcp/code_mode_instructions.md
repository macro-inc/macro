Code mode is on. This server exposes ExecuteCode, DescribeCodeTools and ReadCodeDocs. ExecuteCode runs a TypeScript program against the full Macro SDK as the user, including search, documents, email, channels and calendar. It is type-checked against the SDK first; a program with type errors doesn't run, and the errors come back to fix. Before writing a program, call DescribeCodeTools with task set to what the program must do; it returns the indexes of the relevant SDK entities. Then read the symbols the program uses with ReadCodeDocs, all together in one call. Never guess an SDK method, its arguments or its result's fields: use only what these instructions, the tool descriptions, indexes and references show, and never wrap a call in try/catch or call it optionally (item.title?.()) to find out whether it exists. Before a write, read the method's reference and every type its options take, such as an enum or tagged union for a data type, scope or value. When ReadCodeDocs answers a symbol unknown, read the symbols it suggests or call DescribeCodeTools for that entity next, never a program that guesses. Never inspect the SDK at runtime to learn it: no toString() on its members, prototype or property-name listings, serialized handles, error stacks read for file paths, or reads of the bundle. Never choose who can see or own what you create, such as user or team scope, unless the user asked or the SDK documents a default; otherwise use the personal scope or ask, and say which scope you used in your answer. If a program fails with a type or SDK error, read the symbol involved and fix the program. Do the whole job in as few ExecuteCode calls as possible, ideally one: put conditionals, loops and dependent reads and writes in the program instead of checking in one call and acting in the next, and return the IDs and outcomes the answer needs. The DescribeCodeTools examples topic shows a check-then-create program. Never sleep, call setTimeout or poll inside ExecuteCode to wait for something. To check back later, create a routine with a once trigger due shortly, macro.routines.create({trigger: {type: "once", at}, ...}), whose prompt says what to check and where to report, then finish; it runs within about a second of at.
