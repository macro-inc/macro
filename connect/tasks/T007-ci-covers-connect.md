# T007: CI runs on Macro Connect changes

## Goal

A change under `connect/` triggers the same CI as one under `crates/` or
`services/`: Rust tests for affected packages, clippy, and the ast-grep rules
(including the `connect-*` boundary rules).

## Context

- Generated workflows: `tooling/xtask/crates/xtask_workflows/src/workflows/`
  (`code_check_conventions.rs`, `code_check_cloud_storage.rs` and its
  directory). `.github/workflows/*.yml` are generated by `cargo x workflows`;
  never edit them by hand.
- `tooling/just/check.just` already includes `connect/` (planner change).

## Do

1. Find every generated workflow whose path filters list `crates/**` or
   `services/**` for Rust checks or ast-grep, and add `connect/**` alongside.
2. Make sure the affected-package selection used by the Rust test workflow
   (look for how it maps changed paths to packages) treats `connect/` paths
   as workspace packages.
3. Regenerate with `cargo x workflows` and keep tests in `xtask_workflows`
   passing; add or update a test if the generator has fixtures for filters.

## Done when

- `cargo x workflows --check` passes.
- `cargo nextest run -p xtask_workflows` passes except the two known
  `build_dmg_on_tag` fixture failures caused by Nix's PATH (state whether they
  still fail).
- `just check` passes.

## Out of scope

Workflows unrelated to Rust or ast-grep; new workflows.

## Result

  `tooling/xtask/crates/xtask_workflows/src/workflows/code_check_cloud_storage.rs`

- Added `connect/**/Cargo.toml` to the cargo-deny trigger in
  `tooling/xtask/crates/xtask_workflows/src/workflows/cargo_deny.rs`.
- Regenerated `.github/workflows/code_check_cloud_storage.yml`,
  `code_check_conventions.yml`, and `cargo_deny.yml`.
- Added filter coverage in
  `tooling/xtask/crates/xtask_workflows/src/workflows/code_check_cloud_storage/test.rs`
  and verified that a Connect path selects its workspace package in
  `tooling/xtask/crates/xtask_nextest_filter/src/test.rs`. The selector needed
  no implementation change.
